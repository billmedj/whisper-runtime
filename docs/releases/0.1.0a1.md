# 0.1.0a1 — alpha

Date: 2026-09-07.

First alpha of the Python API and `whisper-runtime` CLI. Transcribes one English
audio stream with `tiny.en`. Input is mono 16 kHz audio. TXT, SRT and VTT exports
contain confirmed text and are written after successful completion and cleanup.

Select `--profile low-latency-v2` for earlier confirmed text, or
`profile="low-latency-v2"` in Python. It reuses alignment features for the same
audio window and checks agreement across two observations. Token drafts are off.
The default remains `conservative-v1`; existing profiles are unchanged.

CUDA startup prepares the aligner's CPU backtrace before accepting audio.
Model inference and Triton kernels are not warmed up.

## What was checked

We ran the same 46.55-second clip twice on one T4, feeding audio in real time.
First confirmed text arrived at 7.358 s and 6.186 s after readiness. The longest
gap between confirmed-text updates was 7.679 s.

Both runs processed all 744,800 samples, returned capacity and produced identical
TXT/SRT/VTT files. Each transcript had 7 word edits against a 114-word reference.
These short, repeated-input tests do not establish typical accuracy or latency.
Times exclude setup, transport and display.

See the [measured results](../research/2026-09-07-low-latency-v2-gpu-results.md)
and [verified evidence archive](../../evidence/modal-low-latency-v2-2026-09-07.zip).
