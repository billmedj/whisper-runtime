# Single-stream T4 endurance result

The registered short test and 30-minute source-paced test complete on one T4,
using one loaded `tiny.en` FP32 model and two successive sessions. The worker
and model identities match. Neither model weights nor publication checks change.

| Measurement | Short test | Long test |
| --- | ---: | ---: |
| Source duration | 46.55 s | 1,800 s |
| Accepted and committed samples | 744,800 | 28,800,000 |
| Accepted chunks | 2,328 | 90,000 |
| Commits before and at EOF | 4 | 118 |
| First provisional text after READY | 4.255 s | 2.428 s |
| First commit after READY | 31.156 s | 28.901 s |
| EOF to verified DONE | 0.892 s | 0.884 s |
| Peak buffered source audio | 30.76 s | 28.80 s |
| Final buffered audio | 0 | 0 |
| Word edits / reference words | 7 / 114 | 266 / 4,332 |

Both stages pass the registered transport, input-hash, sample-coverage and
cleanup checks. The short test's word-edit rate is 6.14%, below the fixed 10%
development threshold. Supplemental offline scoring finds the same 6.14% on
the long output. It does not introduce or change a registered acceptance gate.

The long source repeats the same 46.55-second speech/noise/silence cycle 38
times, then adds 31.1 seconds of digital silence. This tests sustained execution,
not 30 minutes of independent speech. Word errors remain. Sample coverage alone
does not prove correct recognition. Committed spans crossing recipe boundaries
are not assigned a per-arm quality score.

PyTorch live allocations are 160,720,896 bytes both before and after the warm
long session. This is not peak VRAM, reserved memory, process memory or a general
memory bound. No matched stock-Whisper speed comparison was run here. Long-stage
commit arrival minus source-span end has a 0.653 s median and 2.994 s p95; these
are not word or stable-caption latency. First stable text takes almost 29 s.
